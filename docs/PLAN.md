## 1. 技術スタックの推奨と根拠

| レイヤ | 採用 | 根拠 |
|---|---|---|
| 言語 | Python 3.11+ (実機は 3.14) | Windowsで環境構築が容易、PDFライブラリが充実 |
| GUI | **PySide6** | サムネイルグリッド(`QListView` の IconMode)とドラッグ&ドロップ並べ替えが標準で揃う。Tkinterで同等のUIを作ると自前実装が増え、かえって重く壊れやすくなる |
| ページ描画 | **pypdfium2** | Chromiumのpdfium系。描画が速くライセンスが緩い(BSD/Apache) |
| ページ操作 | **pypdf** | 結合・分割・削除・回転・並べ替えはこれで完結。純Pythonで依存が軽い |
| 画像処理 | **Pillow** | pypdfium2 のビットマップ→PNG/JPEG 保存 |
| 圧縮 | **Ghostscript(外部プロセス呼び出し)** | 画像再圧縮を伴う本格的な軽量化はGhostscriptが最も確実。Python単体では品質・圧縮率ともに大きく劣る |
| パッケージング | venv + `run.bat` | 単独利用のため exe 化の優先度は低い |

### ライセンスに関する注意

- PyMuPDF(fitz)は高速で便利だが **AGPL** のため、配布を考えるなら避けたい。今回は個人利用だが、将来の配布可能性を残すため **pypdfium2 を採用**する。
- Ghostscript も AGPL。当初は「同梱配布はせず、ユーザーが別途インストールしたものを検出して呼び出す」
  方針だったが、**2026-09-13 に本人の判断で exe への同梱に変更した**（利便性を優先）。
  AGPLは配布・ネットワーク越しの利用に対して組み合わせた成果物の完全なソース提供を義務づける。
  本人1台での利用に閉じている間は実質問題にならないが、**この exe を将来誰かに渡す・公開する場合は
  本リポジトリのソース一式も一緒に提供すること**（`scripts/bundle_ghostscript.py` 参照）。
  ソースからの実行(`run.bat`)は引き続き「外部インストールを検出」方式のまま変更していない。

## 3. 機能仕様

### 3.1 圧縮(compress.py)

**目標サイズ指定による反復探索方式**

```
入力: PDFパス, 目標サイズ(MB), 最低品質の下限
処理:
  1. 画像解像度(dpi)とJPEG品質のペアを候補として二分探索
  2. 各試行で Ghostscript を実行し、出力サイズを測定
  3. 目標サイズ以下で最も高品質なものを採用
  4. 下限に達しても目標を下回らない場合は、達成できた最小サイズを返し
     「目標未達」であることを明示して返す
出力: 生成PDFパス, 実サイズ, 試行回数, 達成/未達フラグ
```

Ghostscript の基本コマンド:

```
gs -sDEVICE=pdfwrite -dCompatibilityLevel=1.5 -dNOPAUSE -dBATCH -dQUIET \
   -dDetectDuplicateImages=true \
   -dDownsampleColorImages=true  -dColorImageResolution={dpi} \
   -dDownsampleGrayImages=true   -dGrayImageResolution={dpi} \
   -dDownsampleMonoImages=true   -dMonoImageResolution={dpi*2} \
   -dJPEGQ={quality} \
   -sOutputFile={out} {in}
```

要件:
- 探索は **最大6回程度**で打ち切る(毎回フル実行するため時間がかかる)
- 進捗を UI にコールバックで返す(「3回目を試行中 / 現在 7.2MB」など)
- プリセット(高品質・標準・最小)も裏で同じ仕組みの固定パラメータとして用意しておく

### 3.2 画像書き出し(export.py)

- 既定: **200dpi / PNG**(2026-09-12 に150→200へ変更)
- dpi と形式(PNG/JPEG)は UI から変更可能にするが、初期値は上記
- ページ範囲指定: 全ページ / 選択ページ / `1-5,8,10-12` 形式の文字列指定の3通り
- 出力ファイル名: `{元ファイル名}_p001.png` のゼロ埋め連番
- 出力先は **元PDFと同じ場所に作った専用サブフォルダ**（`yy-mm-dd_元名_png/`）

### 3.3 ページ操作(pageops.py)

対象: 結合 / 分割 / 削除 / 回転(90度単位) / 並べ替え

**設計方針**: 操作のたびにファイルを書き出すのではなく、**メモリ上の「ページ参照リスト」を編集し、保存時に一度だけ書き出す**。

```python
# ページ参照の最小単位のイメージ
@dataclass
class PageRef:
    source_path: Path   # 元PDF(結合時は複数ファイルが混在しうる)
    source_index: int   # 元PDF内でのページ番号(0始まり)
    rotation: int       # 0/90/180/270 の累積回転
```

- 編集中の状態は `PageRef` のリストとして保持
- 並べ替え・削除はリスト操作、回転は `rotation` の更新のみ
- Undo/Redo は操作前のリストのスナップショットをスタックに積む単純方式でよい
- 分割は「選択したページ群を別ファイルとして書き出す」として実装

### 3.4 サムネイルビューアー(thumbnail_view.py)

- `QListView` + `QAbstractListModel` + IconMode
- **遅延読み込み必須**: 表示範囲に入ったページだけレンダリングし、`QPixmapCache` に保持。100ページ超のPDFでも起動が固まらないこと
- サムネイル生成はワーカースレッドで行い、完了時にモデルへ通知
- 複数選択(Ctrl/Shift)、ドラッグ&ドロップでの並べ替えに対応
- ダブルクリックでそのページの拡大表示(単一ページの別ウィンドウで十分)

### 3.5 バッチ処理(batch.py)

- フォルダを指定し、直下の `.pdf` を一括処理(サブフォルダは含めない。オプションで含められるようにする)
- 対応する操作: **圧縮** と **画像書き出し** の2つ(ページ操作はバッチ対象外)
- 進捗バーと、処理結果の一覧(ファイル名 / 元サイズ / 後サイズ / 成否)を表示
- 1件が失敗しても全体は止めず、最後にまとめて報告する

## 4. 非機能要件

1. **原本を絶対に上書きしない。** すべての出力は新規ファイル。同名が存在する場合は連番を付与
2. **出力ファイル名規則**: `yy-mm-dd_元ファイル名_処理内容.拡張子`
   例: `26-09-12_進路資料_compressed.pdf`、`26-09-12_進路資料_p001.png`
   → `utils/naming.py` に集約し、各機能はここを経由すること
3. **日本語パス対応**: ファイルパス・ファイル名に日本語・空白を含む前提でテストする。Ghostscript への引数渡しは `subprocess` にリストで渡し、シェル経由にしない(`shell=True` 禁止)
4. **重い処理は必ず別スレッド**: 圧縮・書き出し・サムネイル生成中に UI が固まらないこと
5. **Ghostscript 未検出時**: 起動時に検出し、見つからなければ圧縮機能のみ無効化して警告表示。他機能は動作すること
6. **エラーは握りつぶさない**: 暗号化PDF・破損PDF・0ページPDFを想定し、ユーザーに何が起きたか日本語で伝える

## 5. モデル分担(Opus / Sonnet)

コスト最適化のため、以下の方針で切り替える。**フェーズ境界でモデルを切り替えること。**

### Opus で行う(設計判断と壊れやすい中核)

- **Phase 1**: `core/document.py`, `core/compress.py`
  - とくに目標サイズの探索アルゴリズムは試行錯誤が必要な部分。ここは Opus
- **Phase 2**: `core/pageops.py`
  - `PageRef` モデルと Undo の設計。ここを間違えると全体が破綻する

  - 遅延読み込みとスレッド境界の設計まで。中身の作り込みは次フェーズ
- 加えて、各フェーズ完了時点での **core の公開インタフェース(関数シグネチャと戻り値の型)を確定させ、docs/API.md に書き出す**こと
